# Identity2 - Handoff de portage 1.21.8 -> 1.21.11

Date: 2026-02-25  
Branche source: `1.21.8`

Ce document resume les changements appliques en 1.21.8 pendant la phase de correction, afin de les reporter proprement en 1.21.11 (meme si les classes/methodes ont bouge).

## 1) Variants non reconnus (Wolf/Cat/Frog)

### Probleme
En 1.21.8, les registres variants (`CAT_VARIANT`, `WOLF_VARIANT`, `FROG_VARIANT`) ne sont pas toujours accessibles directement via `BuiltInRegistries.<FIELD>`.

### Correctif
- Fallback de resolution:
  1. essayer `BuiltInRegistries.<FIELD>`
  2. sinon `Registries.<FIELD>` (ResourceKey)
  3. puis `BuiltInRegistries.REGISTRY.getValue(resourceKey.location())`
- Application de ce fallback a:
  - application de variante au morph,
  - extraction/sync de variante,
  - decouverte de variantes cote client.

### Fichiers (source)
- `common/src/main/java/net/Gabou/identity2/mixin/EntityMixin.java`
- `common/src/main/java/net/Gabou/identity2/identity/IdentityProgression.java`
- `common/src/main/java/net/Gabou/identity2/client/identity/IdentityVariantDiscovery.java`

## 2) Effets d'attaque manquants (Cave Spider / Wither Skeleton)

### Correctif
Injection serveur sur `Player.attack(Entity)` (TAIL), avec verification de la cible (`getLastHurtByMob`):
- Morph `minecraft:cave_spider`: Poison
  - Normal: 140 ticks
  - Hard: 300 ticks
- Morph `minecraft:wither_skeleton`: Wither 200 ticks (hors Peaceful)

### Fichier
- `common/src/main/java/net/Gabou/identity2/mixin/PlayerEntityMixin.java`

## 3) Respiration morph (etat stale bulles d'air)

### Correctif
- Reset air sur morph non aquatique hors eau pour eviter bulles stale.
- Morph aquatique:
  - en eau: reset air max
  - hors eau: decrement air + degats associes

### Fichier
- `common/src/main/java/net/Gabou/identity2/mixin/EntityMixin.java`

## 4) Vol morph / conflit vol creatif

### Objectif
- Eviter les etats bloques de vol quand on change de morph/gamemode.
- Conserver le fait que chicken ne donne PAS un vrai vol libre.

### Correctif
- Centralisation de la decision vol via `IdentityTraitTags.resolveFlight(type)` + fallback heuristique.
- Application du grant/revoke de `mayfly` via `applyIdentityFlightGrant(...)` (respect creatif/spectateur).
- Plus de forgage brutal `flying=true`/`mayfly=true` dans les chemins de morph.
- `minecraft:chicken` reste hors `can_fly` (pas de vol libre).

### Fichier
- `common/src/main/java/net/Gabou/identity2/mixin/EntityMixin.java`

## 5) Delai de grace quand morph vers une grosse entite

### Objectif
Quand la hitbox augmente, eviter les degats instantanes de collision/suffocation pendant un court delai.

### Correctif
- Nouveau key NBT: `identity2.morph_damage_grace_end_tick`.
- Sur morph:
  - comparer ancienne taille vs nouvelle taille
  - si croissance: grace de 40 ticks
  - sinon: clear grace
- Hook degats:
  - immunity temporaire pendant grace pour `IN_WALL`, `FLY_INTO_WALL`, `CRAMMING`.

### Fichiers
- `common/src/main/java/net/Gabou/identity2/identity/IdentityProgression.java`
- `common/src/main/java/net/Gabou/identity2/mixin/LivingEntityMixin.java`
- `common/src/main/java/net/Gabou/identity2/mixin/EntityMixin.java`

## 6) Ender Dragon morph: pas de degats collision en vol

### Correctif
Dans la logique d'invulnerabilite des joueurs morphed:
- si identite courante = `ENDER_DRAGON`, ignorer `IN_WALL`, `FLY_INTO_WALL`, `CRAMMING`.

### Fichier
- `common/src/main/java/net/Gabou/identity2/mixin/LivingEntityMixin.java`

## 7) Rendu animation client (dont Bat)

### Objectif
Reduire les animations "weird" et corriger bat sans anim.

### Correctif
- Sync supplementaire du `WalkAnimationState`:
  - `position`, `positionScale` (pas seulement speed/speedOld).
- Etat use-item:
  - start seulement si source utilise item,
  - sinon `stopUsingItem()`.
- Bat:
  - forcer `setResting(false)`,
  - `flyAnimationState.startIfStopped(...)`,
  - `restAnimationState.stop()`.

### Fichiers
- `common/src/main/java/net/Gabou/identity2/mixin/client/EntityRenderDispatcherMixin.java`
- `common/src/main/java/net/Gabou/identity2/util/LimbAnimatorAccessor.java`
- `common/src/main/java/net/Gabou/identity2/mixin/LimbAnimatorMixin.java`

## 8) Main 1ere personne en morph (jamais main joueur)

### Objectif
Toujours afficher la main/partie de l'entite morph, jamais la main vanilla joueur en morph.

### Correctif
- `HeldItemRendererMixin`:
  - no fallback vers main vanilla si morph actif,
  - tentative de resolution de partie du modele (droite/gauche puis fallback partie non vide),
  - texture recuperee depuis le renderer de l'entite via `createRenderState` + `extractRenderState`,
  - clamping des offsets pour limiter les placements extremes.
- Les redirects sont en `require = 0` pour eviter un crash hard si signature bouge.

### Fichier
- `common/src/main/java/net/Gabou/identity2/mixin/client/HeldItemRendererMixin.java`

## 9) Preview entite dans l'inventaire vanilla/creatif

### Objectif
Que le viewer d'inventaire affiche l'entite morph et pas toujours le player.

### Correctif
Redirection de l'appel `InventoryScreen.renderEntityInInventoryFollowsMouse(...)` dans:
- `InventoryScreen.renderBg(...)`
- `CreativeModeInventoryScreen.renderBg(...)`
pour remplacer l'entite preview par l'identite morph si disponible.

### Fichiers
- `common/src/main/java/net/Gabou/identity2/mixin/client/InventoryScreenMixin.java`
- `common/src/main/java/net/Gabou/identity2/mixin/client/CreativeModeInventoryScreenMixin.java`
- `common/src/main/resources/identity2.client.mixins.json`

## 10) Points sensibles de portage 1.21.11 (mappings/signatures)

Verifier en priorite:
1. `ItemInHandRenderer`:
   - `renderPlayerArm`, `renderMapHand`,
   - cibles `PlayerRenderer.renderRightHand/renderLeftHand`.
2. `InventoryScreen` / `CreativeModeInventoryScreen`:
   - presence de l'appel statique `InventoryScreen.renderEntityInInventoryFollowsMouse(...)` dans `renderBg`.
3. `LivingEntity.isInvulnerableTo(...)`:
   - signature exacte (parametres monde/source).
4. `WalkAnimationState`:
   - noms/champs prives `speedOld`, `speed`, `position`, `positionScale`.
5. `Bat`:
   - champs `flyAnimationState` / `restAnimationState`,
   - methode `setResting(boolean)`.
6. Si un injection point n'existe plus:
   - garder `require = 0` temporairement,
   - puis refaire un point d'injection equivalent apres inspection bytecode.
